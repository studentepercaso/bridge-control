# Bridge Control 0.5.4 — Review hardening and attested builds / Hardening della revisione e build attestate

## English

Bridge Control 0.5.4 addresses the current automated Obsidian review without expanding the plugin's authority. The companion no longer imports `node:child_process` and never starts an executable. Its CLI panel now reports only a candidate derived from an explicit override or known installation locations; the external Obsidian Bridge performs the definitive readiness check when an allowlisted CLI-backed operation is actually requested.

The folder picker now excludes the vault's real `Vault.configDir` rather than assuming `.obsidian`. Shared settings migrate to version 5 so this path is also an authoritative deny rule in the external bridge, including whole-vault modes. The dedicated deny is always case-insensitive, closing case-aliases when a Linux vault resides on NTFS, exFAT, or another case-insensitive volume without changing normal Linux allowlist matching. A version-2 through version-4 entry remains deny-all until its own vault records the real path, and any saved folder grant intersecting that path is removed. This migration can only narrow access; it never invents a permission. Equivalent character-code validation replaces the regular expressions that triggered control-character warnings. The release also resolves the reported unnecessary assertion, promise-listener, unsafe assignment, non-`Error` throw, unused import/declaration, timer, and CSS `:has()` findings.

Node filesystem access remains because Bridge Control must coordinate with a separate local bridge process, but it is limited to documented external stores: shared settings and their ownership lock or revocation quarantine; the read-only size-bounded Obsidian registry; authenticated one-time management requests; recovery backups; and metadata-only audit records. Node filesystem APIs are never used for note paths. Every note read or mutation remains on public Obsidian APIs such as `Vault.process`, `Vault.rename`, and `FileManager.trashFile`.

A new GitHub Actions workflow checks the locked source, runs two byte-identical production builds, creates SLSA build-provenance attestations for `main.js`, `manifest.json`, and `styles.css`, and uploads those exact files to a retry-safe draft release. Its manual backfill path first requires the complete published asset set to match a clean rebuild of the exact tag and creates a distinct signed historical-verification predicate rather than claiming that the old assets were built by the backfill run. A local dry run rebuilt 0.5.3 twice identically and matched all three published assets byte for byte; this statement does **not** claim that GitHub attestations for 0.5.3 have already been created.

Version 0.5.4 adds no permission, command, protocol field, network request, arbitrary execution, direct filesystem note write, permanent deletion, or other mutation surface. Install the matching Obsidian Bridge 0.5.4 release and reload Obsidian.

## Italiano

Bridge Control 0.5.4 risolve le segnalazioni della revisione automatica Obsidian corrente senza ampliare l'autorità del plugin. Il companion non importa più `node:child_process` e non avvia mai eseguibili. Il pannello CLI indica ora soltanto un candidato ricavato da un override esplicito o da posizioni di installazione note; Obsidian Bridge esterno esegue la verifica definitiva quando viene effettivamente richiesta un'operazione allowlistata basata sulla CLI.

Il selettore delle cartelle esclude ora il vero `Vault.configDir` del vault invece di presumere `.obsidian`. Le impostazioni condivise migrano alla versione 5 affinché questo percorso sia anche una regola di esclusione autorevole nel bridge esterno, comprese le modalità per l'intero vault. Il divieto dedicato ignora sempre maiuscole e minuscole: chiude gli alias di maiuscole quando un vault Linux si trova su NTFS, exFAT o un altro volume case-insensitive, senza cambiare le normali allowlist Linux. Una voce dalla versione 2 alla versione 4 resta senza accesso finché il proprio vault non registra il percorso reale; ogni ambito salvato che lo interseca viene rimosso. La migrazione può soltanto restringere l'accesso e non inventa mai permessi. Una validazione equivalente basata sui codici dei caratteri sostituisce le espressioni regolari che generavano gli avvisi sui caratteri di controllo. La release risolve inoltre le segnalazioni relative ad assertion non necessaria, listener con Promise, assegnazione non sicura, lancio di valori diversi da `Error`, import/dichiarazioni inutilizzati, timer e CSS `:has()`.

L'accesso filesystem Node resta necessario perché Bridge Control coordina un processo bridge locale separato, ma è limitato agli archivi esterni documentati: impostazioni condivise e relativo lock di proprietà o quarantena per revoca; registro Obsidian di sola lettura e con limite dimensionale; richieste di gestione autenticate e monouso; backup di recupero; record audit composti solo da metadati. Le API filesystem Node non vengono mai usate per i percorsi delle note. Ogni lettura o modifica di una nota resta sulle API pubbliche di Obsidian, come `Vault.process`, `Vault.rename` e `FileManager.trashFile`.

Un nuovo workflow GitHub Actions controlla il sorgente bloccato dal lockfile, esegue due build di produzione identiche byte per byte, crea attestazioni SLSA di provenienza per `main.js`, `manifest.json` e `styles.css` e carica quegli stessi file in una bozza di release ripetibile. Il percorso manuale di backfill richiede prima che l'intero insieme degli asset pubblicati coincida con una build pulita del tag esatto e crea un distinto predicato firmato di verifica storica, senza dichiarare che i vecchi asset siano stati prodotti dal backfill. Una prova locale ha ricostruito due volte la 0.5.3 in modo identico e ha confrontato con successo, byte per byte, tutti e tre gli asset pubblicati; questa frase **non** dichiara che le attestazioni GitHub della 0.5.3 siano già state create.

La versione 0.5.4 non aggiunge permessi, comandi, campi di protocollo, richieste di rete, esecuzione arbitraria, scrittura diretta delle note via filesystem, cancellazione permanente o altre superfici di modifica. Installa la release Obsidian Bridge 0.5.4 corrispondente e ricarica Obsidian.
